## 장의 구성

| 순서 | 절 | 하는 일 |
|------|-----|---------|
| 1 | 이 기술이 없던 시절의 불편 | 이 기술이 왜 등장했는지 |
| 2 | 개념 | 비유로 시작해 실제 파일·코드·메모리 구조로 잇는다 |
| 3 | 다른 방식과 비교 | 독자가 아는 방식과 무엇이 같고 다른지 |
| 4 | 예제 | `examples/`의 실제 프로젝트로 확인한다 |
| 5 | 나쁜 코드에서 좋은 코드로 | 나쁜 코드 → 문제점 → 단계별 개선 → 좋은 코드 → 적용된 원칙 |
| 6 | 직접 확인해 보기 | 로그, 생성된 파일, 디버거로 눈으로 검증한다 |
| 7 | 확인 문제 | 세 문제. 해답은 부록에 있다 |

## 표기 규칙

- 코드 위의 머리줄은 그 코드가 있는 **실제 파일의 경로**이고, 줄 번호는 **그 파일의 실제 줄 번호**다.
- 파일의 일부만 실을 때는 빠진 자리에 `⋮ (중략)` 머리줄이 붙는다.
- **"검증 환경에서"**로 시작하는 결과는 실제로 실행해 얻은 것이고, **"검증하지 못했다"**고 적힌 내용은 문서나 원리에 따른 설명이다.
